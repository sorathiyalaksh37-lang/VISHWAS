## Fixes verified

**Buffer position leak (Issue 1) — FIXED**

Line 243 of VoiceDetectionPage.tsx now includes `bufferPositionRef.current = 0` in stopRecording(), resetting buffer state before session cleanup. Line 176 also resets the counter at the start of startRecording(). The fix prevents stale buffer corruption when stopping and immediately restarting a session.

**ScriptProcessorNode deprecation (Issue 2) — DOCUMENTED**

Lines 207-210 add a comment acknowledging the deprecation and explaining the trade-off: "ScriptProcessorNode is deprecated in favor of AudioWorkletNode, but we use it here for broader cross-browser compatibility. AudioWorklet requires a separate worklet module file which adds build complexity. Modern browsers still support ScriptProcessorNode." This is a defensible choice for a real-time streaming prototype prioritizing compatibility over main-thread performance.

**Session expiry handling (Issue 3) — FIXED**

The sendVoiceChunk() method in api.ts (lines 251-257) now checks for `response.status === 404` and throws a specific error: `throw new Error(\`404: ${errorData.detail || 'Session not found or expired'}\`)`. The processAudio() function in VoiceDetectionPage.tsx catches this (line 148) via `error.message.includes('404')` and displays "Session expired - please restart" before calling stopRecording(). This gives users a clear signal when the 30-minute TTL expires mid-stream.

**Nullable spoof_prob type (Issue 4) — FIXED**

StreamChunkResponse.spoof_prob changed from `number` to `number | null` (api.ts line 173). This matches the backend contract where spoof_prob is null during the insufficient_data phase before enough audio has been analyzed. The component already handled nullability correctly at runtime; this change adds type safety.

**Partial chunk documentation (Issue 5) — DOCUMENTED**

Lines 126-128 of VoiceDetectionPage.tsx document the behavior: "Note: Partial chunks (< 48000 bytes) are dropped when recording stops. This is expected behavior as the backend requires exactly 48000 bytes per chunk." This clarifies that the buffer discard on stop is intentional, not a bug.
